# 客户独立服务计划

版本：v0.3
日期：2026-05-12
关联文档：[AI 客服助手 PRD](./ai-customer-service-prd.md)、[AI 客服 Harmless 安全策略](./ai-customer-service-harmless-policy.md)

## 1. 目标

后续我们不把 AI 客服立即做成完全开放的多租户 SaaS，而是先以“单独服务每个客户”的方式交付。

目标是：

- 每个客户有独立配置、独立知识库、独立会话和独立留资数据。
- 交付流程可复制，但客户数据不混用。
- 前期支持人工实施和运营，后期逐步标准化为自动开通。
- 对普通客户使用轻量隔离，对高敏客户支持独立部署。

## 2. 服务模式

### 2.1 当前阶段：自用单站点

用于验证核心能力：

- 官网 Widget
- DeepSeek 对话
- 官网知识库 RAG
- 会话记录
- 留资收集
- 后台管理

该阶段只有一个客户，即我们自己的官网。

### 2.2 下一阶段：客户专属实例

每个客户开通一个专属服务实例，包含：

- 独立客户 ID
- 独立后台访问入口
- 独立官网嵌入代码
- 独立知识库
- 独立向量索引
- 独立系统提示词
- 独立会话与线索数据

代码可以共用，部署和数据按客户隔离。

### 2.3 成熟阶段：混合架构

未来可以形成两种交付形态：

- 标准客户：共享应用服务 + 数据按客户强隔离
- 高敏客户：独立应用服务 + 独立数据库 + 独立向量库 + 独立密钥

这样既能控制成本，也能满足对数据隔离要求更高的客户。

## 3. 推荐架构

### 3.1 MVP 架构

```text
客户官网
  ↓
客户专属 Widget 配置
  ↓
统一后端服务
  ↓
按 customer_id 隔离的业务数据
  ↓
按 customer_id 隔离的知识库与向量检索
  ↓
DeepSeek API
```

### 3.2 高敏客户架构

```text
客户官网
  ↓
客户专属 Widget
  ↓
客户独立后端服务
  ↓
客户独立数据库
  ↓
客户独立向量索引
  ↓
客户独立模型/API 配置
```

## 4. 隔离策略

### 4.1 配置隔离

每个客户独立配置：

- 客户名称
- 官网域名白名单
- Widget 主题色
- AI 助理名称
- 欢迎语
- 推荐问题
- 系统提示词
- 是否展示来源
- 是否启用留资
- 留资字段
- 日程预约配置
- CRM 对接配置
- 表单/Webhook 对接配置
- 线索字段映射

### 4.2 知识库隔离

每个客户独立管理：

- 官网 URL 列表
- 抓取规则
- 文档来源
- 切块内容
- 向量索引
- 更新时间

RAG 检索时必须强制按 `customer_id` 过滤。

### 4.3 会话隔离

每个客户独立存储：

- 访客 ID
- 会话记录
- 消息内容
- 来源页面
- 当前咨询页面
- 后续扩展：客户官网内页面访问轨迹、停留时长与意图标签
- 命中知识片段
- 未命中标记
- 留资信息

后台账号只能查看绑定客户的数据。

### 4.4 密钥隔离

至少隔离：

- DeepSeek API Key
- Embedding API Key
- 后台登录凭据
- Webhook 密钥
- 数据库连接密钥

MVP 可以先使用平台统一模型 Key；客户开始商业交付后，应支持客户级 Key 配置。

## 5. 客户开通流程

### 5.1 开通前信息收集

需要客户提供：

- 公司名称
- 官网域名
- 需要接入的页面范围
- 品牌色
- AI 助理名称
- 欢迎语偏好
- 推荐问题
- 联系方式与留资字段
- 是否需要展示来源链接
- 是否有不能回答的问题

### 5.2 初始化客户配置

执行：

- 创建客户记录
- 配置域名白名单
- 生成 `site_id`
- 生成 Widget 嵌入代码
- 创建后台账号
- 配置系统提示词
- 配置推荐问题

### 5.3 初始化知识库

执行：

- 添加官网 URL
- 抓取页面
- 清洗正文
- 切块
- 生成向量
- 检查同步结果
- 人工抽查知识片段质量

### 5.4 上线前测试

至少测试：

- 基础公司介绍
- 核心产品能力
- 典型客户问题
- 价格与报价边界
- 合作流程
- 联系方式
- 无答案问题
- Prompt Injection
- 其他客户资料隔离
- 移动端和桌面端展示

### 5.5 正式上线

上线步骤：

- 将嵌入代码交给客户或插入官网
- 验证域名白名单
- 验证前台 Widget 加载
- 验证会话入库
- 验证后台可查看
- 观察首日会话

## 6. 交付物清单

每个客户交付：

- 客户专属嵌入代码
- 客户后台地址和账号
- AI 助理基础配置
- 知识库来源 URL 列表
- 上线测试记录
- 安全边界说明
- 运营建议

内部保留：

- 客户配置记录
- 同步日志
- 测试问题集
- 未命中问题列表
- 客户定制需求记录

## 7. 开发计划

### 阶段 1：自用 MVP

目标：验证完整链路。

范围：

- 单站点 Widget
- 单知识库
- 单后台
- DeepSeek 接入
- pgvector 检索
- 手动同步官网内容
- 会话和留资记录
- 会话创建时记录当前访问页面与来源页面

完成标准：

- 我们自己的官网可以使用 AI 客服。
- AI 能回答官网核心问题。
- 后台能查看会话和未命中问题。
- 后台能看到访客从哪个页面发起咨询。
- 可以手动更新知识库。

### 阶段 2：客户维度改造

目标：让系统具备服务多个客户的基础。

范围：

- 增加 `customer_id` / `site_id` 数据模型
- 所有查询强制带客户范围
- Widget 按 `site_id` 加载配置
- 知识库按客户隔离
- 会话按客户隔离
- 后台账号绑定客户
- 域名白名单校验

完成标准：

- 可以同时配置两个客户。
- 两个客户的知识库互不影响。
- 两个客户的后台只能看到自己的数据。
- 通过测试确认不会跨客户检索。

### 阶段 3：客户专属交付模板

目标：让每个客户开通流程可复制。

范围：

- 客户开通表单
- 初始化脚本
- 默认提示词模板
- 默认推荐问题模板
- 知识库同步检查
- 上线测试清单
- 嵌入代码生成

完成标准：

- 新客户可以在 1 天内完成初始化和测试。
- 开通过程不依赖临时手工改数据库。
- 每个客户都有标准交付记录。

### 阶段 4：高敏客户独立部署

目标：支持更强数据隔离的客户。

范围：

- 独立数据库部署
- 独立向量库
- 独立环境变量
- 独立后台域名
- 独立日志空间
- 独立备份策略

完成标准：

- 可以为一个客户启动完全独立环境。
- 该客户数据不进入共享数据库。
- 独立环境支持升级和备份。

### 阶段 5：访问轨迹与沟通意图分析

目标：把访客当前访问页面和官网内浏览路径转化为销售沟通线索，帮助客户判断访客意图和跟进优先级。

范围：

- Widget 记录当前页面 URL、页面标题、referrer、进入时间、最近心跳和停留时长
- 页面访问事件按 `customer_id` / `site_id` / `visitor_id` 隔离
- 将页面访问事件关联到会话和留资
- 结合页面路径与对话内容生成意图标签
- 在后台会话详情展示当前咨询页面、访问路径、意图评分和高意向原因
- 支持按页面统计咨询量、留资量和高意向会话

完成标准：

- 客户后台能看到每个会话来自哪个页面。
- 客户后台能看到咨询前访问过的本客户官网页面路径。
- 不同客户之间的访问轨迹不能互相查询或合并。
- 系统能给出基础意图标签，例如了解产品、查看方案、询价、预约咨询。

### 阶段 6：线索转化与外部系统集成

目标：把对话框收集到的联系信息转化为客户可直接跟进的业务动作，包括日程预约、CRM 线索同步和表单提交。

范围：

- 对话框收集姓名、手机号、微信、邮箱、公司、需求描述等线索字段
- 将线索与会话、访问路径、意图标签、意图评分关联
- 支持客户级日程预约配置
- 支持客户级 CRM 配置和字段映射
- 支持客户级表单/Webhook 配置和隐藏字段
- 支持线索同步状态、失败原因、外部记录 ID 和重试记录
- 支持后台手动重试同步

完成标准：

- 客户可以选择启用日程、CRM、表单中的一种或多种对接方式。
- 同一条线索可以同时进入 CRM、预约流程和客户表单。
- 同步失败时原始线索仍保留在系统内。
- 每个客户的集成密钥、字段映射、同步日志互相隔离。
- 后台可以看到每条线索是否已同步、同步到哪里、是否失败。

## 9. 权限计划

MVP 权限：

- 平台管理员：可查看所有客户
- 客户管理员：只能查看自己客户
- 客户运营：只能查看会话、线索、知识库状态

后续可增加：

- 只读角色
- 知识库编辑角色
- 线索跟进角色
- 审计角色

## 10. 运维计划

### 10.1 日常监控

需要监控：

- Widget 加载成功率
- API 错误率
- DeepSeek 调用失败率
- 平均回复时间
- 知识库同步失败
- 未命中率
- 留资转化率
- 当前咨询页面分布
- 页面访问到咨询的转化率
- 高意向页面路径

### 10.2 备份

建议：

- 数据库每日备份
- 客户配置变更保留历史
- 知识库切块可重建
- 向量索引可通过原文重新生成

### 10.3 客户变更

当客户修改官网内容或服务范围时：

- 更新 URL 列表
- 重新同步知识库
- 复测核心问题
- 检查是否影响安全边界

## 11. 商业化路线

### 11.1 前期

以项目制服务为主：

- 帮客户配置官网 AI 客服
- 帮客户整理官网知识库
- 帮客户优化提示词
- 提供基础运营报告

### 11.2 中期

形成标准套餐：

- 基础版：官网问答 + 会话记录
- 增强版：留资 + 运营报表 + 知识库优化 + 基础表单对接
- 专属版：独立部署 + 私有知识库 + 定制安全策略
- 转化版：日程预约 + CRM 同步 + 线索字段映射 + 同步失败重试

### 11.3 后期

根据客户数量决定是否做完整 SaaS：

- 自动开通
- 在线支付
- 多成员权限
- 多渠道接入
- 工单/CRM 集成
- 日程预约与销售跟进自动化
- 表单/Webhook/营销自动化集成
- 更复杂的知识库管理

## 12. 风险与对策

### 12.1 定制过多

风险：每个客户需求不同，导致产品难以标准化。

对策：只允许配置层定制，代码层定制必须进入评审。

### 12.2 数据串库

风险：多客户共享系统时出现跨客户数据泄露。

对策：从数据模型、检索逻辑、后台权限、测试用例四层强制隔离。

### 12.3 AI 回答不稳定

风险：客户认为 AI 代表公司做了承诺。

对策：提示词、低置信策略、人工转接、敏感问题保守回答。

### 12.4 交付成本高

风险：每个客户都需要大量人工配置。

对策：沉淀客户开通模板、测试清单、默认提示词和同步脚本。

## 14. 待确认问题

- 第一批客户是否都接受共享应用服务？
- 高敏客户是否需要独立数据库作为默认方案？
- 客户是否可以自带 DeepSeek API Key？
- 客户是否需要独立后台域名？
- 客户数据默认保留多久？
- 是否提供客户数据导出能力？
- 是否需要签署数据处理或保密协议模板？
- 页面访问轨迹默认保留多久？
- 客户是否需要配置哪些页面属于高意向页面？
- 第一批客户常用哪些 CRM 或线索管理工具？
- 日程预约是对接客户日历，还是先使用预约链接？
- 客户现有官网表单是否支持 API 或 Webhook？
- 线索同步失败后是否需要通知运营人员？
