# AI 客服助手 PRD

版本：v0.3
日期：2026-05-12
阶段：MVP 功能规划
目标用户：官网访客、内部运营/销售人员

## 1. 背景

公司希望在官网底部嵌入一个轻量 AI 客服工具。前期主要自用，不做完整 SaaS 客服系统。系统需要读取官网内容，构建知识库与向量检索能力，让访客可以通过文字对话快速了解公司、产品、方案、合作方式，并在必要时留下联系方式供人工跟进。

参考交互方向：

- Wix 类网站客服浮窗
- SmartHunt/增长超人类 AI 助理入口
- 右下角悬浮按钮 + 对话面板 + 推荐问题

## 2. 产品定位

第一版产品定位为：官网 AI 助理插件。

它不是传统在线客服系统，也不是多渠道工单系统。MVP 只解决一条核心链路：

访客在官网提出问题，AI 基于官网知识库回答，并在高意向或无法回答时引导留资。

## 3. 产品目标

### 3.1 业务目标

- 降低官网访客理解成本，让访客不用逐页查找信息。
- 提升官网转化率，引导有需求的访客留下联系方式。
- 沉淀访客真实问题，反向优化官网内容与销售话术。
- 让内部团队先验证 AI 客服的问答效果，再决定是否产品化。

### 3.2 用户目标

- 访客可以快速知道公司是做什么的、能解决什么问题。
- 访客可以直接咨询产品、方案、价格、合作流程等问题。
- 内部人员可以查看对话记录和 AI 没答好的问题。
- 内部人员可以低成本更新官网知识库。

## 4. MVP 范围

### 4.1 第一版必须做

- 官网右下角 AI 助理悬浮入口
- 点击后打开文字对话窗口
- 欢迎语与推荐问题
- 基于官网内容的 RAG 问答
- DeepSeek API 对话生成
- 会话记录存储
- 用户留资收集
- 官网内容抓取、清洗、切块、向量化
- 后台配置欢迎语、推荐问题、API Key、知识库 URL
- 手动触发知识库同步
- 查看对话记录与未命中问题
- 数据模型预留 `customer_id` / `site_id`，为后续单独服务每个客户做隔离准备
- 记录会话创建时的访问页面 `page_url` 与来源 `referrer`，作为后续沟通意图分析的基础数据

### 4.2 第一版不做

- 多 AI 模式，例如 AI 向导、AI 搜索、AI 速览
- 人工客服坐席系统
- 工单系统
- 多租户 SaaS 管理
- 微信、企微、WhatsApp、小程序等多渠道接入
- 语音、图片、文件上传
- 自动报价与复杂销售流程
- 复杂权限体系
- 完整访客浏览轨迹、页面停留时长、沟通意图评分和销售线索自动分级

说明：第一版先不做完整计费型 SaaS，但数据模型已按企业多租户设计。`customers` 表示企业客户，`tenants` 表示企业下的业务空间；知识库、会话、消息和线索都需要带 `tenant_id`，站点和 Widget 只负责官网嵌入与默认租户配置。

## 5. 用户角色

### 5.1 官网访客

可能是潜在客户、合作伙伴、投资/媒体关注者。目标是快速了解公司能力、判断是否匹配需求、获取合作方式。

### 5.2 内部运营/销售

负责配置 AI 助理内容、查看会话、跟进留资、整理高频问题。

### 5.3 管理员

前期可以与运营角色合并。负责 API Key、知识库来源、域名白名单、基础系统配置。

## 6. 核心用户旅程

### 6.1 访客咨询

1. 访客进入官网。
2. 页面右下角显示 AI 助理入口，并记录当前访问页面与来源页面。
3. 访客点击入口，打开聊天窗口。
4. 系统展示欢迎语与推荐问题。
5. 访客点击推荐问题或手动输入问题。
6. 系统检索官网知识库，组合上下文，调用 DeepSeek 生成回答。
7. AI 返回简洁回答，并可附带相关页面链接。
8. 如果问题超出知识库范围，AI 提示需要进一步确认，并引导留资。

### 6.2 内部配置知识库

1. 内部人员进入后台。
2. 添加或编辑官网 URL。
3. 点击同步知识库。
4. 系统抓取页面、清洗正文、切块、生成向量并入库。
5. 后台显示同步结果、失败页面和更新时间。

### 6.3 内部跟进线索

1. 内部人员查看对话列表。
2. 筛选含联系方式、未命中、高意向的会话。
3. 查看完整对话内容。
4. 导出或复制客户信息进行人工跟进。

## 7. 功能需求

### 7.1 网站嵌入插件

#### 7.1.1 嵌入方式

官网通过一段 JS 代码接入：

```html
<script
  src="https://your-domain.com/ai-widget.js"
  data-site-id="SITE_ID">
</script>
```

#### 7.1.2 插件能力

- 在右下角展示悬浮按钮。
- 支持桌面端浮窗。
- 支持移动端底部抽屉或全屏面板。
- 支持关闭、最小化、重新打开。
- 重新打开时保留当前会话上下文。
- 支持主题色、按钮文案、欢迎语从后端配置加载。
- 仅允许白名单域名调用。

#### 7.1.3 默认入口样式

- 入口位置：右下角。
- 入口文案：AI 助理。
- 入口图标：机器人头像或品牌定制图标。
- 打开后窗口宽度建议 380-440px，高度建议 560-680px。

### 7.2 对话窗口

#### 7.2.1 顶部区域

- 显示 AI 助理名称。
- 显示头像。
- 提供关闭按钮。
- 可选：提供放大按钮，第一版可以先不做。

#### 7.2.2 欢迎区域

默认欢迎语：

> 您好，我是 AI 助理。您可以直接向我咨询公司、产品、解决方案或合作方式，我会尽量基于官网内容为您解答。

推荐问题示例：

- 你们公司主要做什么？
- 你们能帮我的企业解决什么问题？
- 有哪些解决方案？
- 如何获取报价或方案？
- 我想预约咨询，应该怎么联系？

#### 7.2.3 消息区域

- 用户消息右侧展示。
- AI 消息左侧展示。
- AI 回复中显示加载状态。
- AI 回复失败时显示可恢复错误提示。
- 单条消息支持换行和链接。
- AI 回答可展示来源页面。

#### 7.2.4 输入区域

- 多行输入框。
- 发送按钮。
- Enter 发送，Shift + Enter 换行。
- 输入为空时不可发送。
- 请求中可禁用重复发送。

### 7.3 AI 问答

#### 7.3.1 回答原则

- 优先基于官网知识库回答。
- 不确定时明确说明不确定，不编造。
- 对销售咨询类问题，回答后引导用户进一步沟通。
- 对价格、合同、法律承诺等高风险问题，使用保守话术。
- 对官网没有覆盖的问题，提示人工确认。

#### 7.3.2 回复结构

常规回复建议结构：

- 直接回答用户问题。
- 补充 1-3 个关键信息点。
- 如果合适，给出下一步行动，例如查看页面、留下联系方式、预约沟通。

#### 7.3.3 无答案策略

当检索结果低于阈值，或模型判断知识不足时：

文案示例：

> 这个问题我暂时没有在官网资料里找到准确答案。您可以留下联系方式，我会帮您记录需求，稍后由同事进一步确认。

### 7.4 官网知识库

#### 7.4.1 知识来源

- 官网首页
- 公司介绍页
- 产品/服务页
- 解决方案页
- 案例页
- 价格或合作页，如有
- 联系我们页
- FAQ，如有

#### 7.4.2 内容处理流程

1. 根据配置 URL 抓取 HTML。
2. 提取标题、正文、页面链接。
3. 去除导航、页脚、广告、重复按钮文案。
4. 按语义段落切块。
5. 为每个切块生成向量。
6. 存入向量数据库。
7. 记录来源页面、标题、更新时间、内容哈希。

#### 7.4.3 切块策略

- 每个切块建议 300-800 中文字。
- 保留标题层级作为上下文。
- 相邻切块可保留少量重叠内容。
- 对短 FAQ 可按问答对独立切块。

#### 7.4.4 更新方式

MVP 支持手动同步：

- 同步全部页面
- 同步单个页面
- 查看同步成功/失败状态

后续可扩展定时同步。

### 7.5 后台管理

#### 7.5.1 登录

MVP 可使用简单账号密码登录。前期只有内部人员使用，不做复杂角色权限。

#### 7.5.2 配置管理

- AI 助理名称
- 欢迎语
- 推荐问题
- 品牌主题色
- 允许嵌入的官网域名
- DeepSeek API Key
- 对话模型名称
- Embedding 服务配置

#### 7.5.3 知识库管理

- URL 列表
- 页面标题
- 最近同步时间
- 同步状态
- 切块数量
- 手动同步按钮
- 删除知识来源

#### 7.5.4 会话管理

- 会话列表
- 访客来源页面
- 访客当前咨询页面
- 后续扩展：会话前访问过的客户官网页面列表
- 首次访问时间
- 最近消息时间
- 消息数量
- 是否留资
- 是否未命中
- 会话详情

#### 7.5.5 留资管理

支持识别或手动收集以下信息：

- 姓名
- 手机号
- 微信
- 邮箱
- 公司名称
- 需求描述

MVP 可先在会话详情中展示，不单独做复杂 CRM。

后续增强：

- 将对话框收集到的联系方式同步到客户 CRM。
- 将高意向访客引导到日程预约。
- 将线索提交到客户已有表单或营销自动化系统。
- 在后台展示每条线索的同步状态、失败原因和重试记录。

### 7.6 数据统计

MVP 统计指标：

- 插件加载次数
- 打开聊天窗口次数
- 用户提问次数
- AI 回复次数
- 知识库未命中次数
- 留资数量
- 高频问题
- 高意向会话数量
- 当前咨询页面分布

### 7.7 访问页面记录与沟通意图分析

该能力作为后续增强功能，不阻塞 MVP 上线。MVP 先记录会话创建时的 `page_url` 与 `referrer`；后续再记录完整访问路径、停留时长和页面行为，用于判断访客沟通意图。

#### 7.7.1 页面记录

Widget 应在访客浏览客户官网时记录当前访问页面，用作会话上下文和销售意图判断。

记录范围：

- 当前页面 URL
- 页面标题
- 来源页面 referrer
- 进入时间
- 离开时间或最近心跳时间
- 停留时长
- 是否在该页面打开 AI 助理
- 是否在该页面发起咨询
- 是否在该页面提交留资

#### 7.7.2 意图分析

系统应基于页面访问行为和对话内容生成沟通意图标签，帮助运营/销售判断访客需求。

意图标签示例：

- 了解公司
- 了解产品
- 查看解决方案
- 查看案例
- 查看价格/报价
- 联系/预约咨询
- 售后或支持
- 高意向采购
- 低意向浏览

#### 7.7.3 高意向信号

高意向信号包括但不限于：

- 访问价格、方案、案例、联系我们页面
- 在关键页面停留较久
- 连续访问多个产品/方案页面
- 咨询报价、合同、交付、定制、预约等问题
- 提交联系方式

#### 7.7.4 后台展示

会话详情页后续应展示：

- 当前咨询页面
- 咨询前访问路径
- 页面停留时长
- 意图标签
- 意图评分
- 触发高意向的原因

#### 7.7.5 隐私边界

- 只记录客户官网内的访问行为。
- 不跨客户记录或合并访客轨迹。
- 不记录其他网站的完整浏览历史。
- 对个人信息和访问轨迹保留删除能力。

### 7.8 线索转化与外部系统集成

该能力作为后续增强功能，接在留资收集和意图分析之后，用于把对话框中收集到的联系信息流转到客户已有业务系统。

#### 7.8.1 触发条件

以下情况可触发线索集成：

- 访客在对话框中提交联系方式。
- AI 判断为高意向会话并引导预约。
- 访客明确提出“预约沟通”“获取报价”“安排演示”等需求。
- 运营人员在后台手动标记会话为有效线索。

#### 7.8.2 日程对接

目标：让访客在高意向场景下完成预约，减少人工来回确认时间。

能力范围：

- 在对话框中展示预约入口或可选时间段。
- 支持将姓名、手机号、微信、邮箱、公司、需求描述带入预约上下文。
- 支持与客户日历系统或预约工具对接。
- 预约成功后在会话详情和线索详情中展示预约时间、参与人和状态。
- 预约失败时保留线索，并提示人工跟进。

#### 7.8.3 CRM 对接

目标：把 AI 客服收集到的线索同步到客户 CRM，方便销售跟进。

能力范围：

- 创建或更新联系人。
- 创建销售线索或商机。
- 写入来源页面、访问路径、意图标签、会话摘要和原始会话链接。
- 记录同步状态、CRM 记录 ID、失败原因和重试次数。
- 支持客户级 CRM 配置，每个客户独立配置密钥和字段映射。

#### 7.8.4 表单对接

目标：兼容客户已有官网表单、营销表单或低代码表单系统。

能力范围：

- 将线索字段提交到客户指定表单接口或 Webhook。
- 支持字段映射，例如姓名、电话、微信、邮箱、公司、需求描述、来源页面。
- 支持固定隐藏字段，例如渠道、活动、站点 ID、线索来源。
- 表单提交失败时进入重试队列，并在后台显示失败原因。

#### 7.8.5 字段映射

标准线索字段：

- 姓名
- 手机号
- 微信
- 邮箱
- 公司名称
- 需求描述
- 当前咨询页面
- 来源页面
- 意图标签
- 意图评分
- 会话摘要
- 会话详情链接

每个客户可配置字段映射，避免不同 CRM 或表单字段名称不一致。

#### 7.8.6 同步策略

- 默认在访客提交留资后自动同步。
- 支持后台手动重试。
- 支持只同步高意向线索。
- 支持只同步包含联系方式的线索。
- 同步失败不影响对话和留资保存。
- 每次同步必须写入日志，方便排查。

#### 7.8.7 隐私与授权

- 同步到 CRM、日程或表单前，需要客户在后台完成集成配置。
- 不将线索同步到未配置或未授权的第三方系统。
- 不跨客户共享集成配置、字段映射、访问令牌或同步日志。
- 对话框应在留资文案中说明联系方式将用于后续联系、预约或方案沟通。

## 8. RAG 流程

用户提问后的处理流程：

1. 接收用户问题。
2. 写入用户消息。
3. 对问题生成查询向量。
4. 从向量数据库检索相关内容。
5. 根据相似度阈值筛选知识片段。
6. 组合系统提示词、用户问题、知识片段和历史上下文。
7. 调用 DeepSeek API 生成回答。
8. 对回答进行安全与格式处理。
9. 写入 AI 消息。
10. 返回给前端展示。

## 9. 技术建议

### 9.1 推荐架构

```text
官网
  ↓
AI Widget JS
  ↓
后端 API
  ↓
会话服务 / RAG 服务 / 配置服务
  ↓
PostgreSQL + pgvector
  ↓
DeepSeek Chat API
```

### 9.2 模型策略

- DeepSeek 用于对话生成。
- 模型名称做成后台可配置项。
- 根据 DeepSeek 官方 API 文档，当前可通过 OpenAI 兼容格式调用；因此 PRD 不把具体模型名硬编码进产品逻辑。
- 默认建议使用成本较低、响应较快的通用聊天模型。
- 对复杂推理不是第一版重点，客服场景优先考虑稳定、快速、可控。

### 9.3 向量数据库

MVP 推荐 PostgreSQL + pgvector。

原因：

- 技术栈简单。
- 数据、会话、向量可以放在同一数据库。
- 适合前期自用和中小规模官网知识库。
- 后期可迁移到独立向量数据库。

### 9.4 Embedding 策略

- Embedding 模型作为独立配置，不与 DeepSeek 对话模型强绑定。
- 可选择本地开源 embedding 服务或第三方兼容 API。
- 所有知识切块需记录 embedding 模型版本，方便后续重建索引。

## 10. 数据模型草案

### 10.1 customers

企业客户表。

- id
- name
- status
- service_mode
- primary_domain
- contact_name
- contact_email
- created_at
- updated_at

### 10.2 tenants

企业下租户空间表。适合按品牌、事业部、客户项目或解决方案线拆分。

- id
- customer_id
- name
- description
- status
- created_at

## 11. API 草案

### 11.1 Widget API

- `GET /api/widget/config?siteId=xxx&tenantId=xxx`
  - 获取插件配置；`tenantId` 可选，缺省时使用站点默认租户。

- `POST /api/conversations`
  - 创建或恢复会话，写入当前 `tenant_id`。

- `POST /api/conversations/:id/messages`
  - 发送用户问题并返回 AI 回复。

- `POST /api/conversations/:id/leads`
  - 保存留资信息。

- `POST /api/page-visits`
  - 后续增强：记录访客在客户官网内的页面访问、心跳和行为事件。

- `POST /api/leads/:id/sync`
  - 后续增强：将指定线索同步到已配置的 CRM、日程或表单系统。

- `POST /api/calendar/bookings`
  - 后续增强：基于对话框收集到的联系信息创建预约。

### 11.2 Admin API

- `POST /api/admin/login`
- `GET /api/admin/conversations`
- `GET /api/admin/conversations/:id`
- `GET /api/admin/knowledge-sources`

- `POST /api/admin/knowledge-sources/:id/sync`
- `DELETE /api/admin/knowledge-sources/:id`
- `GET /api/admin/settings`
- `PUT /api/admin/settings`
- `GET /api/admin/integrations`
- `POST /api/admin/integrations`

## 12. 界面需求

## 13. 安全与合规

- DeepSeek API Key 只保存在服务端，不暴露给前端。
- Widget 调用需校验 siteId 与来源域名。
- 后台需要登录。
- 留资数据需要避免在日志中明文输出。
- 对话内容存储需可删除。
- AI 回答不得承诺合同、价格、法律责任等未经确认的信息。
- 对联系方式等个人信息需要给出合理使用说明。

- 留资转化率

## 15. 里程碑

### 阶段 1：产品与技术方案确认

- 完成 PRD
- 确定技术栈
- 确定官网 URL 范围
- 确定 AI 助理人设与欢迎语

### 阶段 2：MVP 开发

- 开发 Widget 前端
- 开发聊天 API
- 接入 DeepSeek
- 开发知识库同步
- 接入向量检索
- 开发基础后台

### 阶段 3：测试与调优

- 使用官网真实问题测试
- 调整切块策略
- 调整提示词
- 调整未命中阈值
- 修复移动端适配问题

### 阶段 4：官网上线

- 嵌入官网底部
- 观察日志与会话
- 整理高频问题
- 每周优化知识库

### 阶段 5：访问轨迹与意图分析

- 记录访客在客户官网内的页面访问事件
- 将页面访问路径关联到会话
- 结合页面行为和对话内容生成意图标签
- 在后台会话详情展示当前咨询页面、访问路径、意图评分和高意向原因
- 基于意图分析优化推荐问题、销售跟进优先级和官网内容

### 阶段 6：线索转化与系统集成

- 将对话框收集到的联系方式标准化为线索数据
- 支持客户级日程预约配置，引导高意向访客预约沟通
- 支持客户级 CRM 配置，将联系人、线索、商机和会话摘要同步到 CRM
- 支持客户级表单/Webhook 配置，将线索提交到客户已有表单或营销系统
- 在后台展示同步状态、外部记录 ID、失败原因和重试入口
- 支持字段映射、隐藏字段和客户独立密钥配置

## 16. 验收标准

- 官网可以通过一段 JS 成功嵌入 AI 助理。
- 访客可以打开窗口并完成文字问答。
- AI 能基于官网内容回答核心问题。
- AI 不知道时不会编造答案。
- 后台可以查看完整会话记录。
- 后台可以配置推荐问题和欢迎语。
- 后台可以添加官网 URL 并手动同步知识库。
- 系统可以记录并展示留资信息。
- DeepSeek API Key 不会出现在前端代码或浏览器请求中。

后续集成能力验收标准：

- 对话框收集的联系方式可以形成标准线索。
- 线索可以按客户配置同步到日程、CRM 或表单。
- 同步失败不会丢失原始线索。
- 后台可以查看同步状态和失败原因。
- 不同客户的集成密钥、字段映射和同步日志互相隔离。

## 17. 待确认问题

- 官网当前有哪些页面需要进入知识库？
- 是否已有品牌色、机器人头像或 UI 规范？
- 留资字段优先收集手机号、微信，还是邮箱？
- 是否需要 AI 回复中展示来源链接？
- 后台是否需要多人账号，还是单账号即可？
- 初期部署在现有官网服务器，还是独立部署？
- Embedding 服务倾向本地部署还是使用第三方 API？
- 第一批客户优先对接哪类 CRM？
- 日程预约优先使用客户已有日历，还是使用预约链接方式？
- 客户现有表单是否支持 Webhook/API 提交？
- 线索同步失败后需要重试几次、保留多久？
